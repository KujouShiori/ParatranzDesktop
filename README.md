# Paratranz Desktop

paratranz.cn 的 Windows 桌面客户端。界面就是站点本身，翻译工作台的所有功能原样可用；在此之上加了站点没有的东西：屏蔽项目和屏蔽用户、插件、系统通知。

下载在 Releases，使用说明在 wiki：https://github.com/KujouShiori/ParatranzDesktop/wiki 。这份 README 讲怎么跑和怎么实现，用户视角的操作文档（含常见问题）在 wiki 里。

## 运行

需要 Node.js 18 以上。

    npm run setup
    npm start

setup 会在 npm install 之后补一次 Electron 二进制。这一步不能省：npm 11 的 allow-scripts 闸门会跳过依赖包的安装脚本，npm install 报成功但 node_modules/electron/dist 是空的。补装默认走 npmmirror，想用别的源就设 ELECTRON_MIRROR 环境变量。

打成独立可执行文件，产物在 dist 下（便携版和安装版各一个）：

    npm run dist

自检（会真的打开站点并逐项断言屏蔽、插件、窗口唤回、通知轮询是否生效，结果和截图写到设置目录的 selftest 下）：

    npm run selftest

单元测试（屏蔽判定、注入源码、两条网络通道的改写、规则下发与 document-start 重登记、提醒取数适配、插件匹配与注入源码、与主进程实现的一致性）：

    npm test

## 登录

不用在客户端里输密码。屏蔽管理窗口的「登录」一节：先在系统浏览器里打开个人中心，复制那枚 32 位 Token 贴进来，客户端自己在对应账号的会话里换回登录状态，并立刻回查一次账号接口确认成功。

之所以不做「系统浏览器 OAuth 回调」：站点是在 paratranz.cn 上种 cookie，cookie 落进你自己的浏览器，客户端搬不回来。Token 是唯一能把登录状态带进客户端会话的路子。GitHub OAuth 仍然可以在内置窗口里点，两条路都留着。

## 屏蔽项目和用户

- 在项目页 / 用户页右下角点「屏蔽本项目 / 屏蔽此用户」，或在链接上右键，或在菜单里选「屏蔽当前项目 / 当前用户」（Ctrl+Shift+X），或在屏蔽管理窗口顶部点同一个按钮 — 那里的按钮写的是站点窗口当前这一页，切回窗口时会自动跟着变。任何入口都会先弹一个系统对话框确认，页面上的内容无法替你做这个决定。
- 右下角那个悬浮按钮嫌它压住正文的话，在屏蔽管理 → 提醒与行为 里关掉「在项目页 / 用户页右下角显示屏蔽按钮」，默认显示；关掉不影响其它三个入口。
- 列表、搜索、排行榜、成员、讨论、动态里，被屏蔽的项目整条消失；被屏蔽的用户在成员、评论、动态这类流水里整条移除。
- 词条和译文里只把作者显示成「已屏蔽用户」（头像、简介、邮箱一并清掉），绝不删数据行，翻译记录一条都不会少。
- 私信与站内消息默认保留那一行，但作者脱名、正文显示「内容已隐藏（来自被屏蔽用户）」。之所以不整行删掉：站点靠「点开那条会话」清未读，行没了右上角的红数字就永远消不掉。想让行也消失，看下一节。
- 收信人被屏蔽时只脱名，不删行也不藏正文——否则你自己发出去的消息会被一起处理掉。
- 对被屏蔽项目的接口请求不会发出，客户端直接回一个和站点一致的 404，所以卡片、跳转链接、项目子页面都不会漏。
- 直接输入被屏蔽项目的网址会被拦下，页面被一面屏蔽墙盖住。
- 站点自己缓存的项目名（sessionStorage、收藏列表）也会一起清掉。
- 「临时显示」是运行期的开关，只存在于内存：重启后屏蔽自动恢复。可以单独放开某一项，也可以在托盘 / 菜单 / 屏蔽管理里一次性放开全部。
- 解除屏蔽之后：被改写过的内容会自己回来。屏蔽是在数据交给页面之前动的手，所以解除时客户端会替你把那一页重新加载一次；如果页面上还有你没写完的字（译文框、评论框、私信框），就不自动刷，而是在底部给一条提示，你自己点「重新加载这一页」。正被屏蔽墙盖住的页面同样会自动重载。
- 名单存在设置目录的 paratranz-desktop.json，全局共用，不区分账号。可以在「屏蔽管理」里增删、手动按 ID 或用户名添加、导出导入。

## 私信完全隐藏并自动标已读（默认关闭）

屏蔽管理 → 提醒与行为 → 「被屏蔽者的私信完全隐藏，并自动标为已读」。打开后私信列表恢复整行移除，同时客户端调用站点自己的接口把与该人的会话标记已读，红字不会卡住。只处理「我收到的、未读、发信人被屏蔽」的行，同一会话只标一次。

勾选时会先弹二次确认：这一步会改动服务器上的已读状态且不可撤销，效果等同于你在网页上点开那条会话。不打开它就完全不会有这类写入。

## 插件

把 .user.js / .js / .css 丢进设置目录下的 plugins 文件夹就生效，不用改客户端一行代码。支持 Tampermonkey 的头部注释：

    // ==UserScript==
    // @name     我的辅助脚本
    // @match    https://paratranz.cn/projects/*
    // ==/UserScript==

- 头部注释里的 match 与 include 两条规则都认，语义按通配符处理；没写头部的脚本默认在所有站点页面运行。
- 脚本注入到页面主世界，能碰到站点自己的 DOM 和数据。
- 插件排在屏蔽引擎之后运行，先接管 fetch 与 XMLHttpRequest 再轮到脚本，所以插件不能用来绕过屏蔽。
- 单个脚本报错只点名它自己，不会连累其它脚本，也不会带崩屏蔽层。
- 增删或开关之后要重载窗口才生效。客户端不会替你刷新，免得把你正在编辑的译文打断。
- 插件文件夹里的代码等于你本人的权限，只放你自己信任的脚本。

不加载 Chromium 扩展是有原因的：Electron 44 的 ses.extensions 能读清单，但 content script 根本不执行，实测如此。所以插件走自己的注入通道，反而能直接吃现成的油猴脚本。

## 其它桌面能力

- 托盘常驻，关窗口默认只是隐藏，第一次隐藏时会弹气泡告诉你东西去哪了。再运行一次程序（或按全局快捷键）会把窗口唤回来，包括从隐藏状态。不想隐藏就在屏蔽管理里关掉「关闭主窗口时留在托盘」。
- 全局快捷键：Alt+Ctrl+P 唤出主窗口，Alt+Ctrl+B 打开屏蔽管理，Alt+Ctrl+R 切换临时显示。窗口内快捷键在「文件 / 屏蔽 / 视图」菜单里。
- 新消息、被审核提醒：用对应账号已登录的会话去拉取私信、站内消息和公告，过滤掉被屏蔽来源后发系统通知，点通知跳到那个账号的窗口。自己发出去的那条不提醒（列表按时间排序，刚发出去的一条会以新条目出现）。通知到达时任务栏按钮闪烁并叠加红点角标，点回窗口自动清除。
- 提醒的时效：默认每 45 秒完整拉一次（间隔可在屏蔽管理里调，也可以关掉），另外每 5 秒问一次私信未读数，数字涨了立刻去拉完整列表。站点自己的实时推送通道也会被旁听到——注入之后新建或重连的连接能即时触发，但这条只作加速，不承担兜底。
- 多账号：屏蔽管理里新增账号，每个账号一个独立的登录状态窗口，可以同时开多个窗口并行翻译。屏蔽名单和插件是全局共用的。
- 卸载安装版时会一并清掉注册表里 Windows 替本程序建的通知与 AppUserModelID 键，以及设置目录。

## 实现要点

客户端不重写站点，而是加载真实网页，然后在页面自己的脚本之前接管 fetch 和 XMLHttpRequest，把返回的 JSON 过滤之后再交给页面，所以翻译编辑器、机器翻译、术语库、审核流程这些功能不需要跟着站点改版重做。

- 接管时机优先用 CDP 的 document-start 注入；拿不到时退回 dom-ready 注入，代价是首屏可能闪一下再被隐藏。document-start 那段脚本里烤的是注册当时的规则快照，所以规则一变要重新登记（test/injector.js 用一个假 webContents 盯住这件事），dom-ready 也会补一次下发。
- 判定逻辑在 src/shared/pure.js（主进程用）和 src/inject/engine.js（页面里用）各有一份，test/parity.js 会比对两边在同一批真实接口样本上的输出，防止两份实现跑偏。
- 屏蔽对象是按「这个对象是不是项目 / 是不是用户」的签名识别的，不是按裸 ID 匹配——词条 ID 和被屏蔽项目 ID 撞车时不会误删词条，这一点在测试里有专门用例。
- 名单下发只走函数参数，token 不出现在页面能监听到的任何消息里；页面上的按钮只上报意图，改不改名单由主进程的原生对话框决定。
- 插件的匹配规则在编译期拆成纯字符串片段，注入的代码里不出现正则字面量和多层转义；test/plugins.js 直接执行拼出来的那段源码。

## 已知边界

- 翻译工作台的实际编辑流程需要登录，未登录时自检只能验证到公开页面。第一次请自己登录一次，登录状态会留在对应账号的会话里。
- 提醒的取数逻辑对返回结构做了兼容处理（多种列表包裹字段、多种作者字段）。私信与站内消息的字段是实测过的：发信人 fromUser / from，收信人 toUser / to，私信正文是 content 字符串、站内消息正文在 content.text。站点改了字段的话，在屏蔽管理里勾上「记录接口原始结构」，收一次消息后把设置目录下的 shape-dump 发出来即可校准。
- 用户名屏蔽只在按 ID 屏蔽之外做补充：站点里同一个人可能同时暴露 username 和 nickname，优先用 ID 屏蔽。
- 站点加了 CSP 的话，注入路径需要重新验证；目前站点没有 CSP。
